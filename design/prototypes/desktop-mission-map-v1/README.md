# Desktop Mission Room / Living Goal Map V1

## Compared compositions

### Mission Room — selected production default

A dominant current-frontier region, exact owner/agent action, compact causal chapter rail, Goal/Proof document, immutable recent receipts, and a selected inspector.

Best for:

- desktop command and inspection;
- two-second owner comprehension;
- judge demonstration;
- handling one consequential current decision without dashboard competition.

### Living Goal Map — retain as secondary explanation view

A causal spine showing Goal Contract → Plan → Candidate → Acceptance and the current legal node.

Best for:

- explaining why an action is legal;
- showing exact version/candidate binding;
- diagnosing blocked or superseded work.

It is not recommended as the default because it compresses evidence detail and gives causal structure more weight than the immediate owner frontier.

## Shared semantics

Both compositions render the same four synthetic authoritative checkpoints:

1. owner intent awaiting Goal Contract proposal;
2. Goal Contract proposal awaiting owner confirmation/revision;
3. deterministic FAIL awaiting agent correction;
4. PASS plus completion request awaiting owner acceptance.

Agent actions render as non-interactive status. Owner legal actions render as buttons. PASS remains distinct from owner acceptance.

## Prototype boundary

This is a disposable interaction/design artifact. It does not dispatch production Goal Room commands.
