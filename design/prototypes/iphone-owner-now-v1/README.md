# Variant: Owner Now · iPhone V1

## Design stance

A purpose-built iPhone owner control surface: one current frontier, one legal action, details on demand.

## Surface

Primary **Operate**, secondary **Inspect**.

## Key choices

- Layout: compact Goal header → five-chapter compressed journey → dominant Now card → contextual document → persistent action dock → four-tab navigation.
- Typography: native Apple system type with restrained weight and tight display tracking.
- Color: deep neutral canvas; warm amber only for owner attention; teal for agent; periwinkle for internal verifier.
- Interaction: desktop review rail switches four authoritative checkpoints; context collapses; action dock and tabs provide visible feedback.
- Evidence: FAIL and PASS have distinct proof treatments; PASS still leads to owner decision.

## Four checkpoints

1. Owner intent awaiting agent Goal Contract proposal.
2. Goal Contract v1 awaiting owner confirmation or revision.
3. Candidate v1 deterministic FAIL awaiting agent correction.
4. Candidate v2 PASS plus completion request awaiting owner acceptance.

## Trade-offs

- Strong at: one-handed owner decisions, two-second authority comprehension, honest completion semantics, iPhone-native hierarchy, and typed Goal revision with keyboard-constrained layout.
- Weak at: this prototype does not yet implement full tab content or landscape composition.

## Revision interaction

`Request changes` opens a bottom sheet bound to Goal Contract v1. Owner prose is explicitly classified as a Goal Contract revision request. The sheet explains that v1 remains immutable, the request does not confirm a Goal or authorize Plan work, and the agent must propose v2.

## Best for

The owner checking WorkHub intermittently from an iPhone and needing to understand or decide one consequential frontier quickly.

## Prototype boundary

This is a disposable interactive design artifact. It uses realistic synthetic state and does not dispatch production Goal Room commands.
