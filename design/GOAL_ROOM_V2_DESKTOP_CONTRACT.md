# Goal Room V2 Desktop Contract

## Surface

Primary: **Operate/Monitor**. Secondary: Command/Inspect.

The desktop is a Mission Room—not a marketing page and not a grid of equally important dashboard cards.

## Composition

```text
Goal Contract header + current status
→ dominant Now / What Needs You region
→ exact actor and legal frontier
→ context inspector: Goal / Plan / Proof / Discussion
→ lifecycle and receipts through progressive disclosure
```

## Two candidate interaction models

### Mission Room — recommended first

- left/center: dominant current frontier and live work
- right: selected context inspector
- top: compact Goal, version, status, WebMCP connection
- bottom/detail: lifecycle and receipts
- best for daily operating and judge legibility

### Living Goal Map — comparison prototype

- Goal Contract destination at top
- causal Plan path beneath it
- selected task/evidence inspector
- explicit owner gate at Goal/Plan/Acceptance boundaries
- best for causality, but higher risk of visual complexity

## Required hierarchy

1. One Goal and exact confirmation status
2. Current journey chapter
3. One dominant owner-attention or waiting state
4. Current actor and legal next action
5. Exact Plan/evidence context
6. Origin/discussion and receipts on demand

## Detail-on-demand rules

- Governance can/cannot explanation moves into contextual help after first exposure.
- Receipts remain accessible but do not dominate the default screen.
- Full hashes appear in Proof inspector; compact digest in Now.
- Plan/Goal revision deltas appear before unchanged full content.
- Conversation context never visually outranks canonical Goal/Plan state.

## Design posture

Use original design drawing principles from precise operational products:

- Linear-like density discipline
- Superhuman-like action focus
- Apple-like spacing and typographic restraint

Do not clone proprietary layouts or branding.

Avoid:

- oversized hero headline
- generic feature cards
- equal visual weight for all panels
- default violet gradient atmosphere
- glass blur
- fake charts or percentages
- decorative agents

## Desktop evidence targets

- 1440×900 primary
- 1280×800 compact laptop
- 1728×1117 large laptop
- Goal owner gate
- Plan owner gate
- FAIL
- PASS
- completion owner gate
- accepted terminal state
- maximum admitted content

## Acceptance test

At 1440×900, the current frontier is the dominant object. A judge can find Goal origin, WebMCP actor action, evidence state, and owner boundary without scrolling.
