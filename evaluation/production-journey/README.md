# Real production Goal Room journey

This directory is generated by `npm run qa:production-journey` from the built production `index.html` / `src/main.ts` entry served at `http://127.0.0.1:4177/index.html`.

## Proof boundary

Agent actions are executed through callbacks captured when the production page registers its six WebMCP descriptors. Owner actions use the visible production forms, buttons, and dialogs through trusted CDP pointer/keyboard input. The production `systemVerifierAdapter` automatically authors deterministic FAIL/PASS records. The harness never imports or navigates to V3 qualification fixtures/replay, never calls `room.dispatch`, `verifyActiveCandidate`, or an Owner controller directly, and bundle scanning rejects qualification markers.

This is **production callback integration proof**, not browser-native WebMCP invocation and not autonomous model selection. Phase 4 alone proves native browser `getTools` / `executeTool` invocation.

## Evidence

- `journey.json`: route, browser/version, six registrations, transition checkpoints, negative controls, exact receipts/final state, composition measurements, modal focus/mutation results, reset disclosure, and screenshot manifest.
- `qualification-receipt.json`: deterministic validation binding, protected-file parity, source hashes, evidence hashes, and the post-commit identity sentinel.
- PNGs: bounded Goal revision, Plan revision, automatic FAIL, automatic PASS/S12, exact S13 modal, sealed S14, phone, and 1199/1200 breakpoint evidence.

The page intentionally keeps state in browser memory. Reload returning to fresh `INTENT_DRAFT` is tested and disclosed as reset, not persistence.

`reporterFailure` is deliberately labeled focused unit/source proof because production composition has no safe reporter-injection seam. It is not misrepresented as a production-browser negative.
